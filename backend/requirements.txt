# NOTE: do NOT add python-magic / python-magic-bin on Windows. python-magic-bin
# ships a 2014-era libmagic DLL that segfaults on load (access violation) under
# modern 64-bit Python, taking the whole process down. Without it, Unstructured's
# detect_filetype falls back to pure-Python detection by file extension — which is
# exactly what parse.py relies on, since it hands `partition` a real `filename=` path
# (the path-only M2 contract) and libmagic content-sniffing never enters the picture.

# Async ingestion layer (Celery + Redis). The worker runs `orchestrate` off a Redis
# queue; broker-only (no result backend — documents.status is the source of truth). The
# `[redis]` extra pulls kombu + a redis client version Celery is tested against (Celery
# caps redis at <6.5, so do NOT pin a bare redis 8.x — it would conflict). On Windows the
# worker must run with `--pool=solo` (the default prefork pool is broken there).
#
# The P3 semantic cache (app/cache.py) REUSES this same redis client — its async surface
# (`redis.asyncio`) ships in the version `[redis]` pulls in — so it adds NO new runtime
# dependency. It runs on a separate logical DB (/1, vs the broker's /0). Keep redis <6.5:
# Celery caps it there, and loosening it to an 8.x would break the worker.
celery[redis]==5.6.3
